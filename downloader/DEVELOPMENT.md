# 3.5.4부터 사용하는 개발 실행

작업 소스:
C:\Users\hynihk\Documents\TAKOH_Media_Downloader_PRO\onews-source\downloader

Chrome에 로드할 확장 전용 폴더:
C:\Users\hynihk\Documents\TAKOH_Media_Downloader_PRO\TAKOH_Development_Extension
소스 폴더에는 Python 캐시가 생성되므로 Chrome에 직접 로드하지 않습니다. 개발 실행이 확장 파일만 전용 폴더에 자동 동기화합니다.

1. 기존 배포 EXE 도우미를 종료합니다.
2. 프로젝트 맨 위의 start_dev.bat을 실행합니다. Python 소스가 실행되며 EXE를 선택하지 않습니다.
3. Chrome/Edge 확장 관리에서 개발자 모드를 켜고 위 TAKOH_Development_Extension 폴더를 압축 해제된 확장으로 한 번 로드합니다. 기존 배포 폴더의 같은 확장은 비활성화해 중복 실행을 피합니다.
4. http://127.0.0.1:5005/studio/에서 테스트합니다.

이후 변경 적용:
- 제작 화면 HTML/CSS/JS: 브라우저 새로고침.
- Python: 파일 저장 시 자동 재시작. 재시작 후 제작 화면을 새로고침합니다.
- 확장 JS/CSS/manifest: 개발 실행 중 저장하면 약 1초 내 전용 폴더에 반영됩니다. 확장 관리의 새로고침을 누른 뒤 대상 사이트도 새로고침합니다. 폴더를 다시 선택하거나 재설치하지 않습니다. 개발 서버가 꺼져 있으면 소스 폴더에서 python dev_extension.py로 동기화할 수 있습니다.

기존 콘텐츠와 작업은 같은 ONEWS/studio 데이터 폴더를 사용합니다. 개발 검증을 격리하려면 start_dev.bat --port 41860 --data-dir scratch/test-data처럼 실행합니다. 실제 확장 연결은 기본 포트 5005를 사용하세요.

분석·후킹 추천·편집 등 제작 요청 중 Python 파일이 바뀌면 요청이 완료될 때까지 자동 재시작을 미룹니다. 테스트 파일 변경은 재시작하지 않습니다. 도우미 창을 종료하거나 프로세스를 강제로 종료하면 요청은 중단될 수 있습니다.
Python을 직접 지정하려면 TAKOH_PYTHON 환경변수에 실행 파일 경로를 넣으세요. 준비된 환경이 없으면 requirements.txt 설치가 필요하다고 안내하며 자동 설치하지 않습니다.

코드 수정과 검증에는 빌드가 필요 없습니다. 사용자가 배포본을 요청할 때만 EXE/ZIP을 만듭니다.

후킹 편집과 자막 처리:
- 원본 분석 화면의 첫 장면 후킹 편집에서 분석 장면을 선택하거나 시작 시간을 입력합니다. 첫 N초를 선택한 N초로 교체하며 이후 구간은 원본 순서로 유지합니다. 선택 장면이 후반부에 다시 등장할 수 있습니다.
- 새 분석에서는 hook 추천을 받습니다. 기존 분석은 관찰 장면에서 직접 선택할 수 있습니다. 6개 대표 프레임에 근거한 추천이며 전체 영상의 동작 품질을 평가한 결과는 아닙니다.
- 편집본은 새 작업으로 저장하고 원본 분석을 시각 매핑하여 재사용합니다. 새 AI 분석으로 기록하지 않습니다. 새 프레임과 음성은 편집본에서 추출합니다. 대본과 게시 상태는 새로 준비합니다.
- 별도 자막 트랙은 출력에서 제외합니다. 화면에 박힌 자막은 사용자가 사각형으로 지정하면 FFmpeg delogo로 주변 픽셀을 보간합니다. 움직이는 자막 자동 감지나 AI 배경 복원은 구현하지 않았습니다. 단순 배경에서만 결과가 자연스러울 수 있으므로 미리보기를 확인합니다.
- Vmake API 호출이나 모델 다운로드는 없습니다. ProPainter는 비상업용 라이선스이므로 포함하지 않았습니다.
참고: https://ffmpeg.org/ffmpeg-filters.html#delogo
참고: https://github.com/sczhou/ProPainter/blob/main/README.md

후킹 추천과 인트로 효과:
- AI로 후킹 장면 찾기는 현재 선택한 모델로 12개 대표 프레임을 비교하는 별도 요청입니다. 상위 3개 후보와 적합도/이유를 저장하고 1순위를 기본 선택합니다. 실제 조회수·전환 확률은 제공하지 않습니다.
- 처음 교체할 구간에만 빠른 줌, 밝기 플래시, 흔들림, 대비 펄스, 흑백→컬러, 페이드 인, 비네트 중 하나를 적용합니다. 원본 그대로도 선택할 수 있습니다. 편집본 미리보기로 효과를 확인합니다.
- 고정 길이 프레임 추출은 전체 동작을 연속 분석한 것이 아니므로 시작 시각과 길이는 직접 확인/수정할 수 있습니다.
참고: https://ads.tiktok.com/resources/help/article/creative-best-practices?redirected=1

작업 재사용과 삭제: 미게시 작업은 기존 작업을 열며, 게시 완료 작업의 재사용은 미게시 파생 작업 하나를 다시 엽니다. 새 파생 작업의 미디어는 같은 디스크에서 하드링크로 공유하고 지원되지 않으면 복사합니다. 작업 삭제는 해당 작업 폴더만 제거하며 다운로드 폴더 파일과 외부 게시물은 유지합니다. 게시 진행 중이거나 결과가 불확실한 작업은 삭제를 막습니다. 기존 중복 작업은 목록의 작업 삭제로 정리할 수 있습니다.

프레임별 자동 텍스트 처리:
- 자동 자막 처리는 RapidOCR 1.4.4의 신경망 텍스트 검출을 모든 프레임에 적용하고, 검출 영역을 확장하여 OpenCV Telea로 메웁니다. 위치가 바뀌는 텍스트도 매 프레임 검출합니다. 시간 일관성을 갖춘 AI 배경 복원 모델은 아닙니다.
- 하단 자막 모드는 중심이 화면 하단 절반에 있는 텍스트만 처리합니다. 전체 텍스트 모드는 위치와 무관하게 처리하므로 제품·간판의 글자도 지워질 수 있습니다. 글자가 없는 그림 로고는 검출하지 않습니다.
- OCR 도구와 모델은 프로젝트의 local_ai 폴더에 설치했습니다. 전역 Python 환경을 변경하지 않았습니다. 복잡한 배경의 제품 모양이나 패턴은 복원 품질을 확인해야 합니다. 원본·편집본은 별도로 보관합니다. 처리 진행 프레임 수를 화면에 표시합니다.
- OpenCV 영상 처리 후 FFmpeg가 원본 음성을 선택한 컷 시각대로 결합합니다. OCR 처리에는 Vmake 또는 기타 유료 API를 호출하지 않습니다.
- 인트로 효과 강도 1~3 중 기본은 2(강하게)입니다. 줌·플래시·흔들림·대비·색상 전환을 기존보다 강조합니다.

후킹 재배치 변경: [후킹 시작~끝] → [원본 처음~후킹 시작] → [후킹 끝~원본 끝] 순으로 연결합니다. 이전의 첫 구간 덮어쓰기 방식은 사용하지 않습니다. 원본 시간 구간이 중복되거나 빠지지 않으며 음성도 같은 순서로 재배치합니다. 이전 편집본은 자동으로 바꾸지 않으므로 저장된 원본에서 다시 생성하세요.

편집 옵션 추가: 음성 전체 제거(mute_audio), 좌/우 상단 [광고](ad_position)를 최종 영상 전체에 적용합니다. 광고 표시는 한글 글꼴로 흰색 글자와 검정 반투명 배경을 렌더링합니다. 인트로 기본 효과는 임팩트 팝(줌+플래시+흔들림)입니다.
자막 삭제 진행률은 처리 프레임/전체 프레임의 백분율이며 완료 후 인코딩 단계는 별도로 표시합니다. 복원은 이전 원본 프레임을 역방향 광학 흐름으로 정렬하고, 이전에 글자가 없으며 추정 배경과 일치하는 픽셀만 재사용합니다. 나머지는 Telea로 보완하고 경계를 부드럽게 합성합니다. 생성형/시간 일관성 AI 복원은 아니며 복잡한 움직임과 항상 가려진 배경은 복원 흔적이 남을 수 있습니다.

제품 중심 줌 개선: 추천 후보에 제품 영역 product_box(x,y,w,h, 화면 대비 %)를 저장합니다. 줌/임팩트 팝의 최대 확대는 1.18배로 제한하고 영역이 큰 제품은 추가로 낮춥니다. 영역이 없으면 확대하지 않습니다. 정확한 후킹 시작 프레임을 hook-frame으로 보여주고 클릭한 좌표 hook_focus를 수동 중심으로 사용할 수 있습니다. 임팩트 팝은 강도를 밝기·대비에 적용합니다. 고정한 중심점이며 움직이는 제품을 프레임마다 추적하는 기능은 아닙니다. 기존 편집본은 원본에서 다시 생성하고 기존 추천은 AI 추천을 다시 실행하거나 중심점을 직접 선택합니다.

대본·제휴·확장 게시 업데이트:
- 대본은 variants 3개(각 500자 이하)를 요청·저장하고 한 안을 선택해 게시 본문으로 사용합니다. 서버 재시작 후 403은 세션 토큰을 갱신하여 한 번만 재전송합니다. 정상 AI 요청은 이 이유로 재전송하지 않습니다. 서버 오류는 JSON으로 반환합니다.
- CLI 할당량 오류만 대체 모델로 한 번 재시도합니다. Antigravity는 계정 목록의 Flash 3.8 실제 ID 또는 설정의 대체 모델 ID를 사용합니다. Codex CLI는 기본 gpt-6-luna 또는 설정 ID를 사용합니다. API로 자동 전환하지 않으며 실제 사용 모델과 시도별 사용량을 기록합니다.
- SerpAPI/쿠팡 Access/Secret 키는 설정 탭에서 Windows DPAPI로 암호화해 credentials.dpapi에 저장합니다. 화면에는 등록 여부만 반환합니다. 시각 검색의 쿠팡 링크 후보를 선택하면 상품을 저장하고 등록된 쿠팡 키가 있을 때 deeplink를 발급합니다. 동일 상품 판단은 별도 확인해야 합니다.
- 첫 댓글은 #광고, 경제적 이해관계 고지, 링크 클릭 안내, 저장한 제휴 링크 순서입니다. 본문 #광고는 유지합니다. 네이버 기본 문구는 https://help.naver.com/service/30027/contents/24104 에서 확인했습니다. 토스 기본 문구는 수정 가능한 일반 수수료 고지 초안입니다.
- 확장 업로드는 준비된 본문/댓글과 영상 스냅샷을 저장하고 Chrome alarms로 실행합니다. 30MB 이하 영상, 로컬 helper 5005, Chrome 실행, Threads 로그인 필요. 반자동은 본문·영상 입력 후 사용자 게시 확인과 첫 댓글 입력 버튼을 제공합니다. 자동은 영상 첨부·본문 게시·새 게시물 확인·첫 댓글 게시 순서입니다. 게시 결과가 불확실하면 자동 재시도하지 않습니다. 예약이 10분 이상 지연되면 missed로 표시합니다. 상태 조회/대기 예약 취소를 제공합니다. 실제 Threads 계정에서 게시 완료 검증은 아직 안 했습니다.
- 이 작업은 빌드하지 않고 개발 확장 폴더만 동기화합니다. Chrome에서 기존 개발 확장을 다시 로드해야 새 alarms 권한과 게시 모듈이 적용됩니다.
