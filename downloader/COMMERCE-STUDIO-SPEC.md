# TAKOH 영상 기반 제휴 콘텐츠 스튜디오

작성일: 2026-10-08
상태: 사용자 요구사항 및 통합 설계. 아래 기능은 현재 배포된 다운로더에 구현된 기능이 아니다.

## 목표와 사용자 흐름

다운로드한 영상 또는 직접 선택한 파일을 분석해 제품 소개 대본과 Threads 본문을 만든다. SerpAPI 검색 또는 직접 입력한 제품 링크로 상품을 선택하고, 사용자 제휴 계정으로 발급된 구매 링크를 연결한다. 영상·본문·광고 고지·구매 유도 댓글을 함께 준비한 뒤 반자동 게시 또는 계정 연결 후 자동 게시한다.

1. 영상 선택: 다운로드 결과에서 선택하거나 로컬 파일을 선택. 미리보기·길이·해상도·음성 유무·출처 기록.
2. 내용 분석: 시간 정보가 붙은 대표 프레임/장면과 음성을 분석. 보이는 제품·동작·사용 장면과 확인되지 않은 브랜드/모델/성능을 분리.
3. 상품 찾기: 관찰 결과를 검색어로 제안하고 SerpAPI로 상품 후보 검색. 사용자가 직접 제품 링크를 넣는 경로도 제공. 외형이 비슷하다는 이유만으로 동일 제품이라고 확정하지 않음.
4. 제휴 링크 연결: 판매처별 공식 발급 경로로 사용자 계정에 귀속된 링크 생성 또는 이미 발급한 링크 등록. 일반 상품 URL과 제휴 링크를 별도 필드로 보관.
5. 대본 생성: 영상의 관찰 근거와 선택 상품의 확인된 정보로 후킹·본문·마무리를 작성. 영상 제작용 대본과 Threads 게시문을 별도로 편집. 실제 사용 기간·할인·최저가·성능을 지어내지 않음.
6. 댓글 준비: #광고, 해당 프로그램의 경제적 이해관계 고지, 구매 유도 문장, 제휴 링크를 조합. 본문에도 광고 식별 표시를 함께 준비하고 게시 형식별 공식 지침을 확인. 댓글만으로 모든 표시 요건을 충족했다고 판정하지 않음.
7. 최종 미리보기: 영상·본문·상품·댓글·게시 계정을 한 화면에서 검토.
8. 게시: 반자동 또는 Threads 공식 API. 본문과 첫 댓글의 실제 결과를 각각 기록.

## 게시 방식

### 반자동

영상 파일·본문·댓글을 준비하고 복사/파일 선택/Threads 이동을 지원한다. 사용자가 게시 결과를 확인할 때까지 `게시 준비` 상태로 유지한다. 글쓰기 창을 열거나 클립보드에 복사한 결과를 `게시 완료`로 기록하지 않는다. 로컬 영상 파일 선택까지 검증하지 못한 구현을 자동 첨부라고 표시하지 않는다.

### 자동

Threads 개발자 앱/OAuth 계정 연결과 영상 전달 경로가 필요하다. Meta 공식 컬렉션의 공개 영상 URL 방식은 로컬 파일 경로로 대체할 수 없다. 공개 저장소 또는 현재 공식 업로드 방식 중 선택한 경로를 구현·검증해야 한다.

미디어 컨테이너 생성 → 미디어 처리 완료 확인 → 게시 → 게시 ID 확인 → 그 ID를 대상으로 광고 댓글 생성/게시 → 댓글 ID 및 부모 관계 확인 순으로 처리한다. 본문 성공·댓글 실패는 부분 성공으로 표시한다. 재시도는 실패한 단계만 수행하고 이미 발행한 본문은 다시 올리지 않는다.

게시 실행은 사용자가 선택한 계정·미디어·본문·댓글에 대한 실제 게시 명령으로 시작한다. 예약 게시가 필요하면 같은 작업 데이터와 상태 검증을 재사용한다.

## 제휴사별 연결 범위

| 서비스 | 검색/직접 입력 | 제휴 링크 발급 방침 |
|---|---|---|
| Amazon Associates | SerpAPI 상품 후보 또는 제품 URL | 국가별 Associates 계정/Tracking ID 및 공식 링크 생성 경로. 기존 링크의 타인 추적 ID를 그대로 유지하지 않음 |
| 쿠팡파트너스 | SerpAPI 후보 또는 쿠팡 제품 URL | 사용자의 파트너스 API 권한·키가 있을 때 공식 딥링크 발급. 판매자 Open API와 혼동하지 않음. 키가 없으면 파트너스에서 직접 발급한 링크 등록 |
| 네이버 쇼핑커넥트 | 상품 URL 또는 검색 후보 | 참여 상품·사용자 자격 확인 후 공식 링크 발급. 공개 변환 API가 확인되기 전에는 공식 화면에서 발급한 링크 등록 지원 |
| 토스쇼핑 | 제품 URL 또는 검색 후보 | 사용자에게 제공되는 제휴 프로그램·발급 문서·계정 권한 확인 필요. 확인 전에는 직접 발급한 제휴 링크 등록 지원 |

SerpAPI는 상품을 찾는 경로다. 검색 결과 또는 임의 `subId`/쿼리 문자열 추가는 제휴 링크 발급 성공의 근거가 아니다. 상품 검색과 각 서비스의 정산 귀속 확인을 별도 상태로 관리한다.

## 통합 구조

- 현재 TAKOH 확장: 다운로드·콘텐츠 선택·스튜디오 진입.
- 통합 스튜디오 화면: 영상, 분석, 상품, 제휴 링크, 대본, 댓글, 게시 상태를 한 작업으로 관리.
- 도우미: 영상 조사/프레임·음성 처리, AI 연결, 상품 검색, 제휴사 발급, Threads 게시 작업 관리.
- 하입덕/인스레드_치트에서 재사용: 레퍼런스 수집·보관함·초안 편집 UI. 고정 템플릿을 실제 비전 분석으로 표시하는 방식, 단순 subId 추가, 확인 없이 published를 기록하는 예약 작업은 교체.
- 키/토큰은 배포 ZIP·로그·공유 문서에 포함하지 않는다. 설정 화면에서 직접 연결하고 로그에는 상태만 남긴다.

## 작업 데이터와 상태

각 작업에 미디어 해시·출처, 분석 모델/범위/시각과 관찰 근거, 상품 ID/판매처/선택 근거, 원본 상품 URL, 발급한 제휴 URL/발급 경로, 대본/본문/댓글 버전, 게시 계정, 컨테이너 ID, 게시 ID, 댓글 ID를 보관한다.

상태: 영상 선택 → 분석 대기/분석 완료 → 상품 선택 → 제휴 링크 준비 → 초안 준비 → 게시 준비 → 미디어 처리 중 → 본문 게시 완료 → 댓글 게시 완료. 오류 상태에는 실패 단계와 재시도 가능 여부를 기록한다. 분석이나 상품이 바뀌면 기존 초안·제휴 링크·게시 준비의 유효성을 다시 확인한다.

## 완료 판정

- 선택한 실제 영상에서 관찰 근거가 생성되고, 그 근거가 대본 입력에 전달되는지 확인.
- 파일명/상품 제목만으로 영상 분석 성공을 표시하지 않음.
- 수동 제품 URL과 SerpAPI 결과가 같은 상품 선택 경로로 이어지는지 확인.
- 각 제휴 링크가 발급 경로를 보존하고 설정된 사용자 계정에 귀속되는지 각 서비스에서 확인.
- 반자동 게시에서는 파일 첨부·본문·댓글 최종 결과를 실제 Threads 화면에서 확인.
- 자동 게시에서는 영상 처리 완료, 본문 ID, 광고 댓글 ID/부모 관계 확인. 부분 실패 및 재시도에서 중복 게시가 없는지 확인.
- 본문·댓글의 광고 고지 누락 및 대본의 확인되지 않은 사용 후기·가격 주장 검사.
- 기존 플랫폼 다운로드 버튼·저장·음성·도우미 배포 회귀 검증.

## 연결 전에 필요한 결정

우선 게시 방식(반자동/자동), 영상 분석 제공자 및 모델, SerpAPI 사용 여부, 제휴 계정별 발급 권한, 자동 게시 시 Threads 앱과 영상 전달 저장소. API 키나 비밀번호를 채팅으로 수집하지 않고 설정 화면에 직접 입력하도록 구현한다.
